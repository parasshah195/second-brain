# T27 — Generate automatic tags and user-trained category prototypes

## Phase
Required core local organisation; optional personalisation.

## Depends on
T03, T13, T22, T23, T24, T25.

## Decision gates
D09 selects assignment models; D10 approves calibrated assignment criteria, thresholds, and budgets. Owner approval is required for pure-law changes. Existing public text requiring per-tag approval is superseded by automatic generation in this task.

## Outcome
Automatically organise accepted launch content with measured high-precision, high-quality local generated tags after save, without per-tag approval, while preserving custom assertions, durable feedback, exact filter semantics, and training that never reinforces its own predictions.

## Context and constraints
`user.tags` is the custom assertion set; `inference.tags` contains generated labels and provenance. Automatic refresh never edits or removes custom tags or user corrections. Explicit promotion creates a custom assertion; rejection and promotion persist across retries, rebuilds, and model changes according to documented scope.

Only manual or explicitly confirmed positive examples train personal category prototypes. Automatic outputs are not training positives, including labels previously generated by the same category. Keep modality and model-version spaces separate. Zero/few examples imply uncertainty, not confident personalized assignment. Cosine scores are not confidence without calibration.

## Implementation scope
1. Apply deterministic known metadata rules first, recording their origin separately from learned inference. Automatically queue local model organisation after save, without waiting for Enter or blocking persistence. Produce automatic labels for eligible items under approved criteria and resource budgets; no per-tag approval workflow is required. Prefer the single compact core model selected through T22; any additional core model requires measured necessity and owner approval.
2. Define inference records with label, origin, score and calibrated confidence where available, source revision, engine/fingerprint, and generated time. Represent missing, pending, failed, and insufficient evidence explicitly.
3. Maintain durable user feedback: custom additions/removals, corrections, scoped rejections, and explicit promotion/confirmation. Define whether rejection applies to an item, category, source revision, or compatible model family before enabling negative-vector behavior.
4. Build prototypes only from eligible user positives with source and fingerprint provenance. Rebuild after eligible training changes and keep text/vision spaces and model versions isolated. Proposed `tag_assignment` code is future work.
5. Preserve exact custom-membership filters; an auto-tag query must carry its distinct origin in the typed AST. Generated tags may drive deterministic automatic-tag Smart Spaces without broadening custom-tag membership.
6. Optionally evaluate bounded opt-in personal ranking boosts through T24. Keep base retrieval and deterministic tie-breaking inspectable; learning and boosts must not become mandatory fine-tuning or hidden ranking dependencies.

## Acceptance criteria
- [ ] Eligible launch items receive useful automatic tags after save without Enter or approval of each label.
- [ ] Independent held-out fixtures meet owner-approved per-content/language precision, recall, coverage, abstention, and latency gates; refusing all tags cannot pass a precision gate.
- [ ] Refresh changes only generated records, never custom tags or corrections.
- [ ] Rejections and promotions survive refresh, cache rebuild, and pack removal.
- [ ] Training logs show only manual/explicitly confirmed positives, excluding automatic predictions.
- [ ] Empty/few-example categories expose uncertainty and compatible-space restrictions.
- [ ] Exact custom-tag filters differ observably from auto-tag Smart Space membership.

## Validation
Keep independent held-out organisation fixtures separate from model selection, threshold calibration, and prototype training. Benchmark core quality on default original content and actual optional losslessly stored content, with all metadata, decoded content and familiar formats preserved. Test default/disabled exact source-byte preservation and enabled lossless safe fallback for unsupported, unverifiable, non-saving and signed inputs. No canonical lossy compression is approved. Report precision, recall, false positives, coverage and abstention by accepted content type and language, alongside CPU-fallback latency and resource use. Evaluate useful automatic model organisation, not metadata-only rules or abstaining on every item. Model-free tests below are visibly degraded recovery tests in addition to healthy bundled-core workflows.

Use synthetic categories with zero, one, and several confirmed examples; include wrong predictions, explicit promotions, contradictory custom assertions, source edits, and model migrations. Refresh repeatedly and verify no self-reinforcing training. Exercise scoped negatives, cache loss, rebuild, cancellation, opt-out boosts, and deterministic Smart Space results. Evaluate assignment calibration and false positives against labeled examples rather than treating cosine as probability. Block networking and disable models to confirm custom organization, save, browse, and FTS remain intact. Run `just check` and `just verdict`; proofs do not establish assignment accuracy.

## Out of scope
Mandatory fine-tuning, automatic promotion into custom tags, training from unconfirmed predictions, cloud labeling, and silently broadened custom filters.

## Handoff
Provide feedback scope decisions, provenance examples, prototype eligibility fixtures, calibration results, and migration behavior to T31 and Smart Space consumers.
